
# Prompt para ChatGPT

**Contexto:**
Estou desenvolvendo o Frontend institucional para um sistema de CAD Service. O Backend (NestJS) já está pronto com APIs para Services, Portfolio e Articles.
Preciso que você analise o plano de implementação abaixo e sugira melhorias, correções ou aponte riscos.

**Objetivo:**
Criar um site institucional Premium utilizando Next.js 14+ (App Router), TypeScript e Tailwind CSS, hospedado no Firebase.

**Plano de Implementação Proposto:**

---

## 1. Arquitetura e Stack
- **Framework**: Next.js 14+ (App Router).
- **Linguagem**: TypeScript Strict Mode.
- **Estilo**: Tailwind CSS com princípios de UI/UX Pro (Dark Mode default).
- **Data Fetching**: Server Components nativos (`fetch`) com cache.
- **Estrutura de Pastas**:
    - `src/features/`: Organização por domínio (portfolio, articles, services).
    - `src/components/ui/`: Componentes reutilizáveis (Botões, Cards).
    - `src/lib/api.ts`: Cliente HTTP centralizado.

## 2. Escopo de Páginas
1.  **Home (`/`)**: Hero section estática + Destaques de Portfólio e Artigos (consumindo API).
2.  **Services (`/services`)**: Listagem de serviços vindos da API `/api/public/v1/services`.
3.  **Portfolio (`/portfolio`)**: Grid de projetos com imagens.
4.  **Articles (`/articles`)**: Blog list.
    - **Detalhe (`/articles/[slug]`)**: Página do artigo (Renderização Markdown/HTML).

## 3. Integração com Backend
- Backend roda em local/cloud.
- Frontend deve consumir direto as APIs públicas (sem autenticação nessas rotas).
- Tipagem: Compartilhar interfaces se possível ou recriar tipos TS no front baseados nas respostas JSON.

## 4. Deploy
- Firebase Hosting (suporte a Web Frameworks experimental ou export estático se possível, mas idealmente SSR/ISR).

---

**Perguntas para análise:**
1. A estrutura de pastas `features/` é adequada para este tamanho de projeto ou seria overengineering?
2. Para um site institucional com SEO crítico, a estratégia de Server Components é a melhor escolha?
3. Quais bibliotecas adicionais você recomendaria para animações sutis (framer-motion?) e renderização de conteúdo rico (artigos)?
